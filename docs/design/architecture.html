Architecture

系统架构与模块边界

RFview 采用“交互前端 + 本地 SigMF/HDF5/RF 核心 + 索引缓存 + 标注工作区”的架构，让 UI 负责理解与操作，让核心引擎负责大文件、安全写回和可复现统计。

总览系统架构SigMF 数据模型数据集管理文件读取与索引HDF5/RadioML统计工具可视化分析标签与元数据技术路线实施路线P0 校准

逻辑分层

层级职责关键对象
Workspace UI数据集浏览、检视面板、图表联动、标注编辑、质量报告和导出向导。Dataset Explorer、Signal Viewer、Annotation Timeline、Report View。
Application Service项目状态、命令路由、撤销重做、任务进度、权限提示和 RFML 导出策略。Command Bus、Job Manager、Undo Stack、Export Plan。
Format Core解析/校验 SigMF meta 与 HDF5 数据集，映射 captures/annotations 或 RadioML frame 标签，处理 extension namespace，安全写回 JSON 或 overlay。SigMFDocument、Hdf5Dataset、RadioMLAdapter、CaptureSegment、AnnotationSegment、Schema Validator。
Signal Core按窗口读取 IQ、格式转换、抽样、FFT/STFT、统计指标、异常检测和 tile 生成。SampleWindow、ChunkReader、SpectrumTile、StatsJob。
Index & Cache数据集目录索引、文件指纹、预览金字塔、统计结果、标签审计和派生 RFML 切片。SQLite Catalog、Tile Blob、Derived Manifest。

端到端数据流

SigMF 文件夹 / Archive / HDF5 文件
  → Import Scanner 发现 .sigmf-meta / .sigmf-data / collection 或 HDF5 X/Y/Z 数据集
  → Format Core 校验 SigMF schema、namespace、captures、annotations 或 HDF5 shape/dtype/chunk
  → Signal Core 按需读取样本窗口并生成预览/统计/tile
  → Index & Cache 保存摘要、质量问题、预计算结果
  → UI 展示数据集健康度、波形频谱、标签时间轴
  → Annotation Service 修改 meta 或 annotations 并版本化写回

不可变原始数据

.sigmf-data 与 .hdf5 默认只读，所有标注、派生切片和质量报告与原始样本分离保存，避免破坏采集数据。

可回放操作

元数据编辑和人工打标签都记录命令日志，支持撤销、审计、导出 patch 以及团队复核。

RFML 就绪

内部统一以“样本窗口 + 标签 + 质量指标 + 切片策略”描述训练样本，便于导出 PyTorch、TensorFlow 或自定义训练清单。

核心边界约定

  • UI 不直接读取大块 IQ 原始数据，只请求抽样序列、频谱 tile、统计表或标注对象。
  • SigMF 写回必须通过 JSON schema 校验、项目规则校验和用户确认。
  • 所有后台任务可取消、可限流、可复用缓存，并可在报告中追踪生成参数。
