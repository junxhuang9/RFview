RFview 推荐技术路线

在先做架构设计、后做程序开发的前提下，技术路线以“本地优先、核心可复用、UI 高交互、缓存可追踪”为原则。

总览系统架构SigMF 数据模型数据集管理文件读取与索引统计工具可视化分析标签与元数据技术路线实施路线

推荐主线

模块建议原因
桌面壳Tauri本地文件访问能力强，打包体积较小，适合 Rust 核心与 Web UI 组合。
核心引擎Rust适合安全解析 JSON、64 位文件偏移、mmap、并发任务、FFT/DSP 和缓存索引。
前端TypeScript + React适合复杂表格、表单、时间轴、命令系统和可视化状态管理。
渲染Canvas/WebGL2 起步，预留 WebGPU满足瀑布图和大规模点图渲染，兼容性优先。
持久化SQLite + tile blobSQLite 保存目录、统计和审计；大块预览/tile 用分块二进制缓存。
SchemaJSON Schema + 项目规则 DSL区分标准合规、项目规则和 RFML 门禁，便于报告和批处理。

备选路线

  • Electron：插件生态和 Web 能力更成熟，但资源占用较高。
  • Qt/QML：原生体验强，但 Web 生态、表单和插件 UI 成本更高。
  • 纯 Web + 后端服务：适合团队协作和数据湖，但 MVP 部署复杂。

核心抽象

  • rfview-core：SigMF 解析、样本读取、统计、tile 生成。
  • rfview-app：工作区、任务、缓存、导出。
  • rfview-ui：React 视图、表单、图表、标注交互。
  • rfview-schema：规则、taxonomy、RFML manifest 定义。

开发前验证建议

在真正编码前，建议先用 3 到 5 组代表性 SigMF 数据做设计校准：小文件、长时间大文件、多 capture、密集 annotation、异常/损坏 meta。确认每个流程在文档层面可解释后再进入 MVP。
