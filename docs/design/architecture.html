Architecture

系统架构与模块边界

采用“前端交互 + 本地核心引擎 + 插件沙箱 + 持久化缓存”的分层架构，避免 UI 直接处理 TB 级原始数据。

逻辑分层

层职责关键接口
Shell / UI工作区、文件选择、布局、快捷键、插件贡献 UI、图表交互。Command API、View API、IPC。
Signal Core样本格式转换、分块调度、FFT、抽样、解调任务编排、缓存写入。ChunkReader、SampleWindow、AnalysisJob。
Storage Adapter本地文件、内存映射、异步读、未来远程 range-read。read_range、map_window、prefetch。
Plugin Host插件发现、权限控制、WASM 运行时、消息路由、资源配额。Manifest、Demodulator API、Result Sink。
Cache / Index文件指纹、元数据、抽样金字塔、FFT tile、用户标注、插件输出。SQLite schema、tile blobs。

数据流

文件 / 远程对象
  → Storage Adapter 按范围读取
  → Signal Core 转为统一 SampleBlock
  → 抽样器 / FFT / 解调插件并行消费
  → Cache 写入可复用结果
  → UI 只接收可视化 tile、统计值和插件结构化结果

此数据流要求所有耗时操作均可取消、可恢复、可限流，并与前端滚动、缩放和跳转操作解耦。

统一样本模型

内部使用 SampleBlock 表示一段连续 IQ 样本，包含文件偏移、样本序号、采样率、中心频率、格式、通道数和校准信息。

任务调度

将预览、FFT、插件解调和缓存构建都表达为有优先级的 AnalysisJob，当前视口任务优先于后台索引任务。

跨平台约束

核心文件 I/O 与 DSP 引擎保持平台无关；平台差异封装在文件映射、GPU 能力探测和系统对话框适配层。
