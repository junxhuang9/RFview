Roadmap

从方案确认到可运行 MVP 的实施路线

本路线将设计确认、核心验证、MVP 和插件生态分阶段推进，降低 TB 文件与插件沙箱带来的工程风险。

总览系统架构技术路径TB 级文件读写解调插件体系多域分析视图实施路线

阶段计划

阶段目标验收标准
0. 方案确认确认本文档中的技术路线、MVP 范围和插件边界。设计文档评审通过，形成待实现任务清单。
1. 技术验证验证 TB 级文件范围读取、抽样预览、FFT tile 和 UI 渲染性能。使用合成大文件完成随机跳转和起点预览演示。
2. MVP实现桌面壳、文件打开、元数据、IQ / 频谱 / 瀑布图和基础缓存。可分析本地 IQ 文件，并支持从文件开始处快速预览。
3. 插件 Alpha实现 manifest、WASM 插件宿主、示例解调器和结果视图。第三方插件可流式接收样本并输出结构化结果。
4. 生态增强插件市场、远程文件、GPU 加速、协作标注和批处理。形成稳定 API 和向后兼容策略。

主要风险

  • 性能 瀑布图 tile 生成和渲染可能成为瓶颈，需要早期压测。
  • 兼容 IQ 文件格式差异大，需允许用户手动补充元数据。
  • 安全 插件能力必须最小授权，避免直接访问敏感文件。
  • API 插件 API 一旦公开需要版本化和弃用策略。

下一步待确认

  1. 桌面壳选择 Tauri 还是 Electron。
  2. 首批支持的样本格式：CI8、CI16、CF32 是否足够。
  3. MVP 是否需要内置某一种示例解调器，例如 AM、FM、FSK 或 LoRa。
  4. 是否优先支持 Windows、Linux、macOS 全平台，还是先聚焦一个平台。
