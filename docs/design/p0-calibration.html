P0 Design Calibration

P0 设计校准结论与进入 P1 的冻结项

本页把现有设计文档收敛为可执行的 P0 校准结果：明确 MVP 边界、SigMF 覆盖范围、RFML 导出契约、质量门禁和 P1 开发入口，避免后续实现阶段反复改方向。

总览 系统架构 SigMF 数据模型 数据集管理 文件读取与索引 统计工具 可视化分析 标签与元数据 技术路线 实施路线 P0 校准

P0 结论

校准结论：RFview 的 MVP 先做本地优先的 SigMF 数据检视、统计、可视化、标注与 RFML manifest 导出；不在 P1-P4 内实现模型训练、云端协作或通用插件市场。P1 可以从“导入代表性 SigMF 数据并生成健康报告”开始实现。

冻结决策

决策域P0 冻结项后续影响
产品定位RFview 是 RFML 训练前的数据理解、治理和标注工具，不负责训练模型。导出 manifest、质量报告和切片计划即可闭环 MVP。
部署形态默认本地桌面应用，推荐 Tauri + Rust core + TypeScript/React UI。P1 先实现可复用 core，再接 UI；远程数据和多人协作延后。
数据安全.sigmf-data 默认只读，元数据写回必须走 diff、校验、确认和审计。编辑器先保存 workspace patch，再提供安全写回。
大文件策略任何视图都按样本窗口读取，首屏只生成必要统计和低分辨率预览。P1 必须验证 sample window reader、文件指纹和缓存失效。
RFML 交付物导出 JSONL/CSV manifest、质量报告、taxonomy 映射和切片计划。后续训练流水线通过 manifest 消费，不直接依赖 RFview 内部数据库。

MVP 内范围

  • 识别本地 SigMF recording、collection 和 archive。
  • 校验 SigMF schema、必填字段、captures、annotations 和项目规则。
  • 展示健康摘要、元数据详情、标签覆盖和质量问题。
  • 提供 IQ、幅度、相位、PSD、瀑布图和标签时间轴联动。
  • 支持 meta 表单编辑、annotation 增删改、diff、撤销和安全写回。
  • 导出 RFML manifest、切片计划、taxonomy 映射和质量报告。

MVP 外范围

  • 不实现 RFML 模型训练、在线推理和模型评测看板。
  • 不要求远程对象存储、权限系统或多人实时协作。
  • 不构建通用插件市场，只预留分析插件边界。
  • 不自动修复高风险元数据字段，必须由用户确认。
  • 不复制或重写大型 .sigmf-data 原始文件。

SigMF 范围校准

对象P1-P4 必须支持处理原则
Globalcore:datatype、core:sample_rate、description、author、license、hardware、recorder、自定义 namespace。保留未知字段；影响样本解释的字段改动触发缓存失效和高风险确认。
Capturecore:sample_start、frequency、datetime，多 capture 边界和采样上下文。sample_start 必须单调；所有样本窗口都附带 capture 上下文。
Annotationsample_start、sample_count、freq_lower/upper、label、comment、confidence、reviewed 和项目扩展字段。校验边界、频带、重叠、最小长度、taxonomy 和 split 泄漏。
Collection/Archive成员索引、相对路径、导入状态、集合级统计和 split。原始文件不复制；索引记录路径、hash、mtime 和派生资产。
Extensionnamespace、版本、schema URL、项目字段。schema 可配置；未知 namespace 原样保存并在报告中提示。

RFML manifest 契约

RFML 导出以“一个训练样本窗口一行”为核心，JSONL 为主、CSV 为辅。字段命名保持稳定，便于 PyTorch、TensorFlow 或自定义训练流水线读取。

{
  "asset_id": "rec_0001",
  "source_uri": "file:///data/example.sigmf-data",
  "meta_uri": "file:///data/example.sigmf-meta",
  "sample_start": 1048576,
  "sample_count": 262144,
  "sample_rate": 2000000,
  "center_frequency_hz": 2450000000,
  "label_id": "mod.qpsk",
  "label_name": "QPSK",
  "split": "train",
  "quality": { "gate": "pass", "warnings": [] },
  "preprocess": { "window": "raw_iq", "dtype": "cf32", "normalization": "none" }
}
  • 必填：asset_id、source_uri、meta_uri、sample_start、sample_count、sample_rate、label_id、split。
  • 可选：中心频率、频带上下界、SNR、confidence、reviewed、scenario、emitter、quality flags。
  • 伴随文件：taxonomy.json、splits.json、quality-report.json、slice-plan.json。

质量门禁

  • 阻塞 meta/data 缺失、datatype 无法解析、文件大小与样本数不匹配。
  • 阻塞 annotation 越界、频带越过 Nyquist、split 中同一 recording 泄漏。
  • 警告 标签覆盖不足、类别极不均衡、SNR 或幅度统计异常。
  • 警告 未复核标签、未知 namespace、统计快照过期。
  • 通过 schema、样本一致性、标签边界、taxonomy 和 split 规则均满足。

P1 代表性样本集

  • 小型干净 recording：验证导入、schema 校验和首屏统计。
  • 长时间大文件：验证窗口读取、低分辨率预览和取消机制。
  • 多 capture recording：验证频率、时间戳和样本段映射。
  • 密集 annotation recording：验证标签时间轴、重叠和覆盖统计。
  • 异常/损坏 meta：验证质量报告、阻塞规则和修复建议。

P1 入口任务

任务最小输出验收方式
SigMF meta parser解析 global/captures/annotations/extensions，保留未知字段。对代表性样本输出结构化摘要。
Schema + project rule validator区分 error/warning/info，生成规则 ID 和修复建议。异常样本能产生健康报告。
Sample window reader按 datatype 和 sample_start 读取小窗口 IQ。读取首屏、标签片段和越界场景。
First-screen stats样本数、时长、幅度摘要、PSD 摘要、标签覆盖。导入后无需全文件扫描即可展示摘要。
Cache skeleton记录路径、hash、mtime、规则版本和统计参数。meta/data 改变后能标记缓存失效。

P0 验收清单

  • 页面结构已覆盖总览、架构、数据模型、数据集管理、文件 I/O、统计、可视化、标注、技术路线、路线图和 P0 校准。
  • 核心流程已闭环：导入 → 校验 → 预览 → 统计 → 标注 → 导出。
  • 字段模型已覆盖 SigMF global/captures/annotations/extensions 与 RFML manifest。
  • 质量门禁已区分阻塞、警告和通过条件。
  • 下一阶段 P1 任务已拆成可实现、可测试的核心验证项。
