🧪 测试项详情 18/20 ✅

✅
Taxonomy 自动提取 1.1 从 annotation 中提取类别
buildTaxonomy() 遍历 currentMeta.annotations， 按 label 聚合 sample_count 统计，按样本数降序排列构建 p4Taxonomy 列表。 每条包含 id、name、count、 pct、color 字段。
📌 使用 getAnnotLabel() 支持 core:label 和 label 两种命名风格。 测试数据（3286 条 annotation，37 个唯一类别）可自动提取。
✅
类别分布显示 1.2 占比条 + 百分比
renderTaxonomy() 渲染表格显示类别 ID、名称、样本数和占比条。 占比条使用 <div class="taxonomy-bar"> 样式（width: item.pct%）， 百分比精确到 0.1%。类别数量显示在 taxonomyCount 徽章中。
✅
类别编辑 1.3 编辑 ID 和名称
Taxonomy 表格中每个类别的 ID 和名称字段都是 <input> 可编辑输入框， change 事件通过 data-tax-idx 和 data-tax-field 属性直接修改 p4Taxonomy[idx][field]。
✅
内置 RadioML 类别 1.4 RADIOML2018_CLASSES 预设
定义 RADIOML2018_CLASSES 常量包含 11 个标准调制类别 （8PSK, AM-DSB, AM-SSB, BPSK, CPFSK, GFSK, PAM4, QAM16, QAM64, QPSK, WBFM）， 与设计文档一致。当标注数据为空但数据已加载时，自动填充预设类别作为占位。
📌 标注中匹配 RadioML 类别时使用 includes 模糊匹配（行 2901）， 可能将包含子串的标签错误归类。示例："BPSK_variant" 也会匹配 "BPSK" 的 mod.bpsk ID。
✅
添加/重置自定义类别 1.5 添加/重置按钮
"添加自定义类别"按钮新建 custom.{name} ID 的类别；"重置"按钮调用 buildTaxonomy() 重新从 annotations 构建。
✅
Train/Val/Test 分配 2.1 分层随机抽样
computeSplits() 按 label 分组后 Fisher-Yates shuffle， 再按配置比例（默认 70/15/15）分配 Train/Val/Test。每组至少 1 条 Train。 p4Splits 保存索引数组。
⚠️ 使用 Math.random() 无种子，每次刷新或重新分配结果不同， 不可复现。建议增加种子随机数生成器以支持可复现的 Split 分配。
✅
Split 比例配置 2.2 数字输入 + 自动归一化
renderSplits() 显示三个数字输入框，支持 0-100 步进 5 的比例配置。 当 sum ≠ 100 时自动归一化（行 3113-3120），舍入误差分配给 Test 并确保 ≥ 0。
📌 归一化逻辑将全部舍入误差放入 Test，可能导致 Test 比例与预期略有偏差（例如 50/25/25 → 50/25/25 不变，33/33/33 → 33/33/34）。
✅
Split 类别分布展示 2.3 按 split 统计类别
Split 面板底部显示类别分布表（Train/Val/Test 三列），展示每个类别在各 split 中的数量。 支持"重新分配"按钮一键重分配。
✅
切片窗口/步长配置 3.1 窗口长度和步长输入
切片预览面板包含 sliceWinInput（窗口长度，默认 1024，范围 64-65536）和 sliceStepInput（步长，默认 512，范围 1-65536）两个数字输入框。 值改变时自动重新计算切片。
✅
Annotation 边界切片 3.2 窗口内 annotation 切分
computeSlices() 找出与当前视口窗口有交集的 annotation， 以 p4SliceWin 长度为窗口、p4SliceStep 为步长进行切片。 最小 slice 长度为 64 样本，生成 start/end/count/label/labelId 字段。
✅
瀑布图叠加 3.3 切片矩形叠加显示
renderSliceOverlay() 在瀑布图（specPlotDiv）上通过 Plotly relayout({ shapes }) 叠加半透明矩形，最多显示 50 个切片。 颜色根据 label 从 TAXONOMY_COLORS 调色板分配。
✅
Manifest 字段完整性 4.1 7 个标准字段
generateManifestRows() 为每个 annotation 生成包含 7 个字段的 manifest 行： source_uri（file:///{dataFileName}#sample_{start}）、 sample_start、sample_count、 label_id（来自 taxonomy 映射）、label_name、 snr_db（从 annotation 或 global 读取）、split（来自 split 分配）。
📌 字段与设计文档（hdf5-radioml.html）中的 manifest 示例相比， 缺少 asset_id、format、sample_dtype 字段。 当前实现使用简化 schema，对下游训练管道仍可正常使用。建议后续版本补充完整字段。
✅
JSONL 格式导出 4.2 每行一个 JSON 对象
exportJSONL() 使用 JSON.stringify(r) 序列化每行， \\n 连接，Blob 下载。文件名格式 {basename}_rfml_manifest.jsonl。 导出前调用 runQualityGate()，门禁未通过时阻止导出。
✅
CSV 格式导出 4.3 含 BOM + 正确引号
exportCSV() 生成 UTF-8 BOM（\\uFEFF）CSV， label_name 使用双引号包裹并转义内部引号（""）。 其余字段直接拼接。导出前同样运行门禁检查。
⚠️ CSV 中 source_uri 字段未用引号包裹，若文件名包含逗号或换行符会导致 CSV 解析错误。 建议所有字段都使用双引号包裹或对 source_uri 单独加引。
✅
门禁-标签覆盖 5.1 ≥ 80% 阈值
runQualityGate() 统计所有 annotation 的 sample_count 之和， 与总样本数比较。≥ 80% 为 pass，50-80% 为 warn，≤ 50% 为 fail。
📌 测试数据（trimmedSamples）中 22372352 总样本，3286 条 annotation 的总样本覆盖可能不足 80%， 实际测试时可能触发 warn/fail。这是数据集特性而非代码问题。
✅
门禁-类别均衡 5.2 最大/最小比 ≤ 10x
按 label 聚合 sample_count，计算最大/最小类别比值。≤ 10 为 pass，10-20 为 warn，> 20 为 fail。 仅一个类别时自动通过。
✅
门禁-数据一致性 5.3 meta/data 匹配校验
检查 global['core:sample_count'] 或 traceability:sample_length 与实际数据大小是否一致。 不一致时标记 warn，缺失声明时跳过检查并标记 warn。
✅
门禁-Split 无泄漏 5.4 索引重复检测
将 Train/Val/Test 的索引合并后检查是否有重复（通过 Set 大小与原始数组长度比较）。 有重复时标记 warn。
✅
门禁阻止导出 5.5 fail 时按钮 disabled
p4GatePassed 综合判定：只要任一检查的 fail 为 true 则阻塞。 Manifest 面板的导出按钮在门禁未通过时显示 disabled style="opacity:0.5;cursor:not-allowed"， 导出函数内也进行二次检查。
📌 综合判定逻辑（行 3532）仅检查 fail，不阻塞 warn 状态。 这意味着标签覆盖 60%（warn）时仍可导出，符合设计意图。
✅
XSS 安全性审查 6.1 P4 代码 innerHTML 使用
P4 代码中所有 innerHTML 赋值均使用 escHtml() 对用户输入进行转义。 共 20 处 escHtml() 调用，覆盖 Taxonomy（label/id/name）、Split（label）、 切片（label）、Manifest 预览（JSON 字符串）、门禁详情（detail）等所有渲染点。
📌 相比 P3 报告中的 XSS 风险，P4 代码已全部使用 escHtml 保护，无新增 XSS 问题。 escHtml() 函数正确处理了 5 个关键字符（& < > " '）。

💡 改进建议

  • CSV 导出全面引号化 — 对所有字段使用标准 CSV 格式（全部双引号包裹），或使用 PapaParse 等库生成稳健 CSV，防止文件名中的特殊字符破坏列结构。
  • 可复现 Split — 引入种子随机数生成器（如 seedrandom.js），允许用户在 UI 中输入随机种子以复现 Split 分配结果。
  • Split 比例实时校验 — 在 <input> 上绑定 input 事件以实时显示比例总和提示，而非等到 change 才归一化。
  • Manifest 字段补充 — 添加 asset_id（默认值 "sigmf." + metaFileName）、format（sigmf.annotation）、sample_dtype（cf32）字段以对齐设计文档。
  • HDF5 适配器 — 当前 viewer.html 不含 HDF5 导入功能，RadioML2018 类别仅为静态预设。建议后续 P5 版本实现 HDF5 数据适配器以导入真实 RadioML2018 数据集。
  • Taxonomy 精确匹配 — 将 includes 改为精确相等匹配或配置化匹配策略，避免误将自定义标签映射为标准调制 ID。
  • 瀑布图叠加性能 — 当前最多显示 50 个切片矩形，对于高频标注场景（>1000 slices）可能需要限制更严或增量更新。
