RFview / 多域射频信号分析软件

类似 IQ Engine 的 TB 级射频信号文件分析平台设计方案

本文档仅用于方案评审：先明确架构、数据流、插件模型、可视化能力与交付路线，待确认后再进入程序实现。

总览 系统架构 技术路径 TB 级文件读写 解调插件体系 多域分析视图 实施路线

设计目标

  • 面向 IQ / RF capture 等大体量信号文件，支持 TB 级数据的低延迟浏览、抽样预览、局部加载与流式处理。
  • 采用类似 VS Code 的扩展机制，使第三方可通过插件贡献解调器、分析器、文件格式解析器与自定义视图。
  • 提供 IQ 时域、频谱、瀑布图、元数据、标注与解调结果等多域联动分析体验。
  • 默认快速定位到文件起点，同时支持任意时间 / 字节偏移跳转、书签、频段兴趣区与渐进式细化。

核心用户流程

  1. 打开本地或远程 RF 信号文件，并读取 sidecar 元数据或由用户补充采样率、中心频率、样本格式。
  2. 系统立即执行文件头部抽样，优先展示文件开始处的 IQ、粗频谱和瀑布缩略图。
  3. 用户拖动时间轴或输入偏移，后台按需映射对应窗口，并逐级提高 FFT / 解调精度。
  4. 用户启用解调插件，插件以流式块接收样本，输出解调比特、符号、包、度量或自定义图层。

优先级范围

MVP 必须具备
本地大文件打开、元数据录入、抽样预览、IQ / 频谱 / 瀑布图、插件加载框架、一个示例解调插件。
后续增强
远程对象存储、分布式预计算索引、GPU 加速、协作标注、在线插件市场、批处理流水线。

建议技术栈

层级建议原因
桌面壳Tauri 或 Electron便于跨平台、文件系统访问、插件 UI 与 WebGL 可视化。
核心引擎Rust适合零拷贝、内存映射、SIMD、并发调度与安全插件边界。
前端 UITypeScript + React/Svelte + WebGL/WebGPU构建复杂交互视图、时间轴、瀑布图和插件面板。
插件 ABIWebAssembly + Manifest跨语言、安全沙箱、版本可控，适合解调算法分发。
预计算缓存SQLite + 分块二进制缓存保存文件指纹、金字塔抽样、FFT tile、标注和插件结果。

推荐技术路径

在现有方案基础上，新增了一页技术路径对比。当前建议以 Tauri + Rust Core + TypeScript 前端 + WebGL/WebGPU + WASM 插件 作为默认主线，同时保留 Electron、原生 Qt/QML 和云端协作三类备选/演进路线。
