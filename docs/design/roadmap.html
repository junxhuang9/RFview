Roadmap

从设计校准到 MVP 的实施路线

本路线把 RFview 分为设计确认、核心验证、可视化标注、RFML 导出和协作扩展五个阶段，避免一开始就陷入完整平台开发。

阶段计划

阶段目标验收标准
P0 设计校准 已完成评审本套 HTML 文档，确定 SigMF 范围、RFML 导出格式和 MVP 边界。已形成 P0 校准结论：页面结构、核心流程、字段模型、RFML manifest 和质量门禁可进入 P1 验证。
P1 核心验证 已实施已新增 Python core/CLI：SigMF 解析、HDF5/RadioML adapter、schema/shape 校验、样本窗口读取、首屏统计和缓存目录骨架。可通过 rfview inspect 导入 SigMF 或 HDF5 文件，输出 JSON 健康报告、质量问题、基本统计和缓存指纹。
P2 可视化 MVP实现数据集列表、IQ/PSD/瀑布、标签时间轴和视图联动。用户能定位异常片段并确认生成数据是否符合预期。
P3 标注与元数据实现表单编辑、annotation 增删改、diff、撤销和安全写回。可完成手工打标签并保存为 SigMF 兼容 meta 或 overlay。
P4 RFML 就绪实现 taxonomy、split 管理、切片预览、manifest 导出和质量门禁。可把通过门禁的数据导出给训练流水线。
P5 扩展能力支持远程数据、多人复核、批处理、分析插件和模型回看。团队可协作治理大规模 RF 数据集。

MVP 必做清单

  • 导入与校验：recording、collection、archive、HDF5/RadioML2018 X/Y/Z。
  • 检视：健康摘要、元数据详情、标签覆盖、质量问题。
  • 统计：幅度、频域、标签、RFML 切片。
  • 可视化：时域、PSD、瀑布、标签时间轴。
  • 编辑：meta 表单、annotation 编辑、diff 与写回。

关键风险

  • SigMF 扩展字段与 HDF5 数据集布局多样，必须保留未知字段并支持 namespace/adapter 配置。
  • 大文件预览性能决定体验，需要优先验证读取与 tile 缓存。
  • 人工标注写回风险高，需要严格 diff、撤销和审计。
  • RFML 导出如果没有质量门禁，容易把脏数据送入训练。

下一步建议

P1 核心验证代码已落地，下一步进入 P2 可视化 MVP：在当前 core/CLI 的健康报告、样本窗口和统计结果之上，实现数据集列表、IQ/PSD/瀑布、标签时间轴和视图联动。
